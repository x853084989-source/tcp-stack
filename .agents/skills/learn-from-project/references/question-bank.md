# 项目题库设计与作答反馈

用于用户明确请求的正式项目题库，以及基于题库的作答练习与反馈。日常少量理解检查沿用 SKILL.md，不自动扩展为整套题库或完整面试训练。

## 生成上下文与面试档位

- 复用当前项目地图、学习记录和用户指定范围，核对适用源码版本、相关未提交改动及实际验证结果；没有证据时注明限制，不把用户自述学完当作全面掌握。
- 进入面试阶段、生成面试项目题时，使用「实习面试」或「校招面试」两个档位。未指定才询问；同次项目检验的面试阶段已有选择时直接沿用，不设为跨任务的永久默认。学习验收、已有答卷批改和讨论阶段不额外询问面试档位。
- 实习面试侧重项目表达、核心流程、基础原理、关键实现理解和真实贡献；校招面试在共同基础上，加强设计取舍、异常边界、排错验证和改进方案的追问。档位是出题侧重点与深度设置，不是公司的统一录用标准。
- 学习验收的核心知识要求依据项目及相关专题确定，不因选择实习档而省略必要基础。

## 阶段与分轮流程

整体规划项目及专题的覆盖范围，按轮生成当前需要的问题，不预先固定所有后续题目。默认先完成学习验收及其补充轮次，再进入面试项目追问及其补充轮次；推进与结束由用户决定，不设强制通过门槛。用户明确只要其中一部分时遵循其范围：

1. **学习验收题库**：检查项目整体、关键机制，以及项目涉及的技术专题基础。专题基础可以覆盖源码未实现的相关机制，不限于解释当前代码所需的最少知识。
2. **面试项目题库**：先给项目介绍，再组织主问题和可能的追问，模拟面试官在不了解源码细节时逐步了解项目。

- 优先使用用户已有的项目介绍；没有时，由助手依据可核实源码、学习与改动记录整理适合口头表达的介绍草稿。区分学习理解、实际参与的修改、独立贡献和已经完成的验证，未知内容标为待确认，不虚构个人经历、实现成果或性能数据。
- 项目介绍是面试官获得的背景，不限制学习验收的覆盖范围。面试问题从介绍及其自然延伸出发，提供回答所需的实现背景，不假定面试官知道私有函数、字段和目录。

每轮流程：

**本轮问题文档 → 用户填写并交卷 → 原答卷红字批改＋本轮参考答案 → 讨论疑问、补充讲解 → 用户提出开始下一轮 → 针对性补题。**

- 题量按当前阶段和必要覆盖确定，不固定所有项目的数量、轮数或代码比例，不按文件、函数或辅助实现逐项配题。已有题库可以作为选题背景，不代替依据本轮回答和讨论生成补题。
- 沿用项目检验资料的位置，每轮主要保留「问题与作答」「参考答案」两份 Markdown。初次只交付本轮问题与可填写区域；参考答案在用户交卷批改后另存并交付，不提前作为本轮附件发布。
- 轮次在同次项目检验中连续编号，进入面试阶段也不重置；题号使用 R01-Q01 等跨轮唯一形式，并注明所属阶段、适用项目和源码范围。已交付题号保持稳定，参考答案按同一题号对应。

## 问题与作答文档

每题包含必要情境、明确问题及「我的回答」区域，以可替换的占位文字预留位置，允许用户自由扩展，不限制字数或要求固定回答模板。例如：

```markdown
# 第01轮｜学习验收

适用项目与源码：按实际范围填写。

### R01-Q01｜题目标题

题目内容，交代影响答案的必要条件。

**我的回答：**

（请在此填写，可自由扩展。）
```

用户填写整个文档后交卷，按整轮答卷批改。空白、未替换的占位文字或明确表示未作答的内容记为未作答，不直接判为答错，也不阻止批改其他题。不因原回答不完整就改写、补全为用户已经答出的内容。

## 题目设计与深度

- 学习验收采用「先综合、后局部」：首轮以解释完整行为、主要模块配合及数据或状态交接的综合问题为主，不要求一次讲完所有细节；后续轮次依据答卷与讨论检查局部环节，按需用条件变化或纠错题检验理解。不把所有题机械套成同一模板。
- 每题提供足够情境，交代会改变答案的必要条件，聚焦明确的主要问题。多个问题需要逐层推进时拆成主问题和可选择的追问，避免一道题堆叠过多任务。
- 默认深度为「机制解释＋场景推导」：能说明主要过程和设计原因，并分析关键条件变化后的结果。对项目涉及的技术专题较系统地检查基础知识，按重要性分层，不扩展为无边界的通用课程。
- 源码题围绕决定行为的关键条件、状态更新、数据交接、对象生命周期和必要的并发安全。以口头说明、流程图或伪代码为主，按需给少量短代码；不默认要求默写或补全完整实现、记忆私有名称或冷僻参数、展开全部内部算法及数学推导。
- 同一机制可从学习验收和面试表达两个角度检查，但不机械地改写成多道重复题。算法练习和限时编程不自动混入本题库。
- 按专题或题目分别标明「项目是否实现」与「是否已经学过」，未知则写待确认。项目未实现不等于用户未学过，也不自动排除该专题基础。与项目直接相关但尚未学习的内容标为「拓展／待补」，不直接作为已学部分理解失败的依据。

例如，接收队列、任务队列或缓冲区中仍有剩余工作时，可以要求推导下一次读取、调度或通知的结果；题目交代具体模型与必要条件，不要求背项目中的辅助函数名。更换项目时围绕其真实机制选场景，不固定照搬某个协议栈的功能清单。

## 参考答案与技术依据

- 用户交卷批改后提供本轮参考答案，独立于原答卷保存，按本轮题号对应，不将所有后续轮次答案一次提前交付。
- 按需交代核心结论、因果、必要前提、重要边界和可接受的不同表达，不将答案写成必须逐字匹配的唯一话术。与通用机制不同的项目简化须明确说明。
- 判断项目实际行为时核对当前源码；通用技术事实必要时核对官方文档、标准或原始资料。参考答案与当前证据冲突时更正答案；证据不足或存在合理分歧时明确说明，不凭旧笔记或用户措辞判错。
- 对待补题说明所需前提及建议补充的知识，不将尚未讲过的内容写成已完成教学或已检验通过。

## 原答卷红字批改与逐题诊断

- 直接在原答卷每道题的用户回答后追加「批改」，保留原题、原始回答和用户批注。按整轮完成批改，证据不足处注明待确认，不等待逐题回复才交付整轮批改结果。
- 批改正文采用红色内联 HTML，每段独立设置，保留明确的文字标签。例如：

```html
<span style="color: #e53935;">批改：主要过程正确，但遗漏了一个会改变结果的条件：……</span>
```

- 批注文字中的 HTML 特殊字符按需转义；不要在 span 内嵌套复杂 Markdown。必要代码块或图保留正常 Markdown 格式，不将整题或整篇答卷包进 HTML。此写法适用于 Obsidian 支持的局部 HTML 样式，见 [官方 HTML 说明](https://help.obsidian.md/Editing+and+formatting/HTML+content)；检查结果须区分文档结构检查与实际阅读器显示，未经阅读器实测不声称红字效果已验证。

不设总分，围绕回答具体检查：

- **结论**：是否符合题目条件，有无关键事实错误。
- **因果**：能否解释过程与原因，区分不同数据、状态、通知或操作的作用。
- **前提与边界**：是否遗漏会改变答案的重要条件。
- **场景应用**：条件变化后能否继续推导结果，不只复述熟悉流程。

反馈说明正确部分、错误或遗漏及理由，按实际问题区分处理：

- **表达问题**：意思基本正确，修正术语或歧义，不因措辞或私有名称记忆不足判为机制错误。
- **局部缺口**：主线正确，指出遗漏的条件或环节，在批改后的讨论中按需针对性澄清。
- **关键误解**：结论或因果存在根本问题，先指出并解释，后续按需要用相近场景检查理解，不反复让用户猜测缺少的前提，也不在批改时自动生成下一轮试卷。

- 接受合理的自然语言、图和伪代码表达；正确术语不掩盖因果错误，表述不同也不等于答案错误。面试反馈可进一步指出是否答中问题，以及贡献或验证表述是否有证据支持。
- 区分独立回答、提示后回答、查阅后回答和讲解后复述，必要时说明本次结论依据哪类表现；这些均可用于学习，但不作完全相同的掌握推断，一次答对不直接证明长期掌握。
- 阶段反馈汇总「已有回答证据的部分、仍有疑问的部分、待补内容」，给出具体下一步，不自动换算成笼统掌握等级、独立开发能力或面试通过率。用户决定推进节奏，不以通过考试或完成实验作为继续学习的强制条件。

## 讨论回填与下一轮补题

- 批改后先回答用户的疑问、补充讲解。把值得保留的重要澄清按题号补回原答卷，在对应题目后用红字追加「讨论补充」，保留用户原回答和初次批改记录，不重复堆叠聊天全文。例如：

```html
<span style="color: #e53935;">讨论补充：本题后来澄清的条件是……；仍需确认的是……</span>
```

- 发现初次批改有误时，在原题处明确标注更正与理由，避免过时结论被当作正确答案；必要时同步订正本轮参考答案。讨论后澄清的内容与原先独立答出的内容分别说明，不把讲解后的理解写成最初就已掌握。
- 用户消化并明确提出开始下一轮后才出下一轮问题；普通追问、讨论或单独表示听懂，不自动视为要求新一轮试卷，不在批改时同时交付下一轮问题。
- 补题综合原答卷中的关键缺口、讨论中已经澄清与仍有疑问的内容、尚未覆盖的核心知识，以及值得通过新场景确认的理解。局部题也补查综合回答未覆盖的关键内容，减少已经讲清内容的重复，不以已经出过题推断已经理解。

## 结束时的汇总

- 用户决定结束时，沿用项目检验资料位置整理「总问题清单」「总参考答案清单」，并保留各轮答卷、批改、讨论和参考答案，便于回查。
- 两份总清单均按学习验收在前、面试项目追问在后组织，各部分按主题整理；只包含实际开展过的内容，不将未进行的面试或其他阶段写成已经完成。
- 合并同义重复题，保留有独立价值的场景与变式；保留代表题原编号，注明原轮次、原题号及合并来源，两份总清单题号对应。
- 总答案采用核实、订正后的结论，仍待确认之处明确标注。汇总不覆盖或改写用户原始答题证据，也不以资料汇总完成推断全面掌握。
