# 学习中的报错与诊断格式

仅在项目学习中收到编辑器、编译、链接或运行错误时使用。普通修 Bug 任务不因读到本参考而自动转成项目学习。

- 先呈现类似 VS“错误列表”的 Markdown 表格；表格前至多一句必要背景，不先铺开长篇排查。列为 编号｜级别｜诊断信息｜文件｜行号｜来源。
- 级别和来源按实际证据填写，区分编辑器诊断、编译器错误、警告、运行日志和源码推断。文件可定位时给链接；未提供的文件名、行号或诊断代码标为“未提供”，不猜测。源码疑点标为“待核实”，不写成已经出现的报错。
- 保留足以识别问题的原始信息。重复或同根因诊断可合并并说明关联，不在表格混写修改建议或长篇原理。
- 表格后按编号给出“修改：……”和“原理：……”，默认各用一两句话。指出具体改动或检查动作，确有必要时附最小代码片段；用户要求时再深入。
- 优先处理当前错误及直接原因。只有影响当前处理的问题才补充，不把一个错误扩成完整审查。
- 用户仅要说明或验证步骤时，只提供相应内容。用户明确要求修改或执行时，按已授权范围操作并报告验证层次；未运行或未验证的效果如实注明。
